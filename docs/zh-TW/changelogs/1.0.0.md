## 新功能與變更

### 透過系統瀏覽器的桌面與主控台登入

`LoopbackOAuth2Client` 讓桌面與主控台應用程式透過系統瀏覽器與 loopback 回呼登入，一律使用 PKCE，可在 Windows、macOS、
Linux 上使用。見[桌面與主控台應用程式](../guides/desktop.md)與 [ADR-004](../../adr/adr-004-system-browser-loopback.zh-TW.md)。

### 不依賴 HTTP 框架的授權碼流程

`OAuth2Client` 把授權碼流程分成 `CreateAuthorizationRequest` 與 `CompleteAuthorizationAsync` 兩個步驟，兩個網頁套件以外的
伺服器端框架也能使用。見[其他伺服器端框架](../guides/other-server-frameworks.md)。

### Token 與 refresh

`TokenResponse` 帶著 access token、refresh token、ID token，以及 token 類型、有效期限與 scope。
`AuthorizationResult.Token` 帶著它，每個 client 的 `RefreshTokenAsync` 可以取得新的 token。
見[結果、token 與錯誤](../guides/results-and-errors.md)。

### ASP.NET Core 註冊

`AddOAuth2Client` 在 ASP.NET Core 應用程式註冊 client、`OAuth2Manager` 與 data protection。見 [ASP.NET Core](../guides/aspnetcore.md)。

### provider 回傳的錯誤

協定層級的失敗擲出 `OAuth2Exception`。`Error` 與 `ErrorDescription` 帶著 provider 回傳的錯誤代碼與說明。

### Provider

- `AzureOAuth2Options.Tenant`：給只註冊在單一 Microsoft Entra ID tenant 的應用程式使用。
- Okta provider（`OktaOAuth2Options`）。`AuthorizationServerId` 設為空值時改用 org 授權伺服器。
- LINE provider 從 ID token 讀取 email。
- Facebook 改用 Graph API v26.0，Google 改用現行的授權與使用者資訊端點。

### HTTP client、取消與標註

- 每個 client 都可以傳入 `HttpClient`，非同步方法都接收 `CancellationToken`。
- Polhem.OAuth2 新增 net10.0 目標框架，這個目標沒有任何套件相依。
- 公開 API 加上 nullable 參考型別標註。

### 安全性強化

- 每次登入都產生新的隨機 state 與 PKCE code verifier，網頁應用程式在回呼之前以加密並驗證的方式保存它們。
  登入用的 cookie 以 `__Host-` 為前綴，並設為 Secure、HTTP-only、SameSite=Lax。
- loopback 監聽程式只接受 Host 標頭為回呼網址主機、且帶著本次登入 state 的請求，並且同時讀取多條連線。
- provider 端點必須使用 https；見[檢查 options 並預設開啟 PKCE](#檢查-options-並預設開啟-pkce)。

## 破壞性變更

### 套件命名空間與目標框架改變

- **影響對象：** 所有參考 Bee.OAuth2 的應用程式。
- **原本：** 套件是 `Bee.OAuth2`、`Bee.OAuth2.AspNet` 與 `Bee.OAuth2.AspNetCore`，命名空間為 `Bee.OAuth2` 系列。
  Bee.OAuth2.AspNet 的目標框架是 .NET Framework 4.8，Bee.OAuth2.AspNetCore 是 net8.0 並參照
  `Microsoft.AspNetCore.Http.Abstractions` 套件；套件相依 `Bee.Base` 與 `Newtonsoft.Json`。
- **現在：** 套件 ID 與命名空間以 `Polhem.OAuth2` 開頭。Polhem.OAuth2.AspNet 的目標框架是 .NET Framework 4.7.2，
  Polhem.OAuth2.AspNetCore 是 net10.0 並參照 ASP.NET Core 共用框架。JSON 改用 System.Text.Json 解析，netstandard2.0
  組建以套件參照它；套件不再相依 `Bee.Base` 與 `Newtonsoft.Json`。
- **遷移：**
  1. 依[從 Bee.OAuth2 遷移](../guides/migrating-from-bee-oauth2.md)的對照表替換套件參照與 `using` 指示詞。
  2. 使用 Polhem.OAuth2.AspNetCore 的 ASP.NET Core 應用程式改用 net10.0。
  3. 原本經由這些套件使用 `Bee.Base` 或 `Newtonsoft.Json` 的應用程式，自行參照它們。
- **背景：** [ADR-001](../../adr/adr-001-drop-bee-base.zh-TW.md)

### 桌面套件由 `LoopbackOAuth2Client` 取代

- **影響對象：** 使用 `Bee.OAuth2.WinForms` 或 `Bee.OAuth2.Desktop` 的桌面應用程式。
- **原本：** 登入在內嵌的 WebView2 視窗中進行。
- **現在：** 這兩個套件與內嵌視窗都已移除。改由 Polhem.OAuth2 的 `LoopbackOAuth2Client` 透過系統瀏覽器登入。
- **遷移：**
  1. 以 `LoopbackOAuth2Client.SignInAsync` 取代同步的 `Authorization()`。`Caption`、`Width`、`Height`、`AuthorizationForm`，
     以及桌面版的 `OAuth2Client`、`OAuth2Manager`、`StateStorage` 沒有替代品。
  2. 依[登記 loopback 回呼網址](../guides/desktop.md#登記-loopback-回呼網址)重新把回呼網址登記為 loopback URI。只在內嵌瀏覽器裡
     有效的網址，例如 `https://login.microsoftonline.com/common/oauth2/nativeclient`，已無法使用。
- **背景：** [ADR-004](../../adr/adr-004-system-browser-loopback.zh-TW.md)

### 不再公開的型別

- **影響對象：** 使用 Bee.OAuth2 provider 類別或 state 儲存的程式碼。
- **原本：** 各 provider 類別、`IOAuth2Provider`、`BaseOAuth2Client`、`IStateStorage`、`PkceHelper`、`OAuth2StateCryptor`，
  以及網頁套件的 `OAuth2Client` 與 `StateStorage` 都是公開的。
- **現在：** 它們已從公開 API 移除。
- **遷移：** 改用 options 型別（例如 `GoogleOAuth2Options`）搭配 client 或 manager。

### 結果與使用者資訊改為唯讀

- **影響對象：** 建立、修改或繼承 `AuthorizationResult` 或 `UserInfo` 的程式碼，以及讀取 `AuthorizationResult.AccessToken` 的程式碼。
- **原本：** 兩個型別都可以修改，結果只帶著 access token。
- **現在：** 兩者都改為 sealed 且唯讀，`AuthorizationResult.Token` 取代 `AccessToken`。
- **遷移：** 讀取 `Token.AccessToken`；refresh 改用 client 的 `RefreshTokenAsync`，它回傳 `TokenResponse`。

### 網頁登入保存在 cookie

- **影響對象：** 使用 Bee.OAuth2.AspNet 或 Bee.OAuth2.AspNetCore 的網頁應用程式。
- **原本：** 進行中的登入保存在 session state，搭配 `OAUTH2_STATE_KEY` 環境變數；manager 提供 `GetAuthorizationUrl` 與
  `ValidateAuthorization`。
- **現在：** 每次登入各自保存在一個 cookie 裡，以 ASP.NET Core 的 data protection 或 `MachineKey` 保護。
  `OAuth2Manager` 提供 `CreateAuthorizationUrl`、`RedirectToAuthorization`、`CompleteAuthorizationAsync` 與 `GetClient`。
  ASP.NET Core 版的方法接收 `HttpContext`，System.Web 版的 `RegisterClient` 接收 options。
- **遷移：**
  1. ASP.NET Core 以 `AddOAuth2Client` 註冊每個 client，System.Web 以 `OAuth2Manager.RegisterClient(name, options)` 註冊。
     應用程式沒有其他用途的話，移除 session state 的設定與 `OAUTH2_STATE_KEY`。
  2. 以 `CreateAuthorizationUrl` 取代 `GetAuthorizationUrl`，以 `CompleteAuthorizationAsync` 取代 `ValidateAuthorization`。
  3. 升級前開始的登入在升級後無法完成，使用者要重新登入。
- **背景：** [ADR-005](../../adr/adr-005-web-sign-in-cookie.zh-TW.md)

### 檢查 options 並預設開啟 PKCE

- **影響對象：** 所有應用程式，透過它傳入的 options。
- **原本：** `UsePkce` 預設為 `false`，建立 client 時不檢查 options。
- **現在：** client 建立時會複製並檢查 options。端點必須是絕對的 https URI，Auth0 與 Okta 的 `Domain` 只接受 https。
  `UsePkce` 預設為 `true`。網頁端的 client 只要設了 client secret 就一律送出，開啟 PKCE 時也一樣；loopback client 只送給 Google。
- **遷移：** 修正被檢查拒絕的 options。client 建立後再修改 options 不會影響那個 client，請改為建立新的 client。
  見[所有 provider 共用的 Options](../guides/options.md)。

### 非預期的例外會往外拋

- **影響對象：** 從 `AuthorizationResult.Exception` 讀取所有失敗的程式碼。
- **原本：** 結果收納登入過程中的任何例外。
- **現在：** `AuthorizationResult.Exception` 只收納 OAuth2 登入預期會發生的失敗，其他例外會往外拋。token 端點回傳的錯誤會
  成為 `OAuth2Exception`。例外訊息會帶 HTTP 狀態碼，但不帶回應內容。
- **遷移：** 讓非預期的例外交給應用程式的錯誤處理，provider 的錯誤代碼從 `OAuth2Exception.Error` 讀取。
  見[結果、token 與錯誤](../guides/results-and-errors.md)。
- **背景：** [ADR-003](../../adr/adr-003-exception-semantics.zh-TW.md)

### 使用者資訊的值改變

- **影響對象：** 保存 `UserInfo` 值的應用程式，尤其是 Microsoft Entra ID 的使用者識別碼。
- **原本：** 值為 JSON null 的欄位是空字串。Microsoft Entra ID 的使用者識別碼讀取 `oid`，沒有 `oid` 時才讀 `sub`。
- **現在：** 值為 JSON null 的欄位是 `null`，備援欄位因此會生效，例如 Auth0 的 `name` 為 JSON null 時改用 `nickname`。
  Microsoft Entra ID 的使用者識別碼讀取 `sub`，這是 OpenID Connect 使用者資訊端點回傳的欄位。
- **遷移：** 把 `null` 當作沒有值。保存了從 `oid` 讀到的 Microsoft Entra ID 識別碼的應用程式，因為 `sub` 與 `oid` 不同，
  要重新對應使用者，例如以 email 對應。見[識別使用者](../guides/identifying-users.md)。
