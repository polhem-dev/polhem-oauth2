# Polhem.OAuth2 1.5.0 — 發佈說明

[English](../../en/changelogs/1.5.0.md) | **繁體中文**

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[1.5.0]` 條目的詳細內容。

本版確立有後端的應用程式如何登入：由後端跑登入，網頁、行動應用程式，以及這一版新增的桌面應用程式都一樣，前端不再把
token 交給後端。沒有後端的應用程式照舊直接登入。決策記錄在 [ADR-011](../../adr/adr-011-back-end-signs-in.zh-TW.md)。

## 新功能與變更

### 桌面應用程式經由後端登入

`LoopbackRelayClient` 讓桌面與主控台應用程式，以及 .NET MAUI 應用程式的 Windows 平台，經由自家 ASP.NET Core 後端的中轉登入：

- 它產生 PKCE 的 code verifier、在 loopback 位址監聽，並以它收到的回呼網址與 S256 code challenge 向應用程式取得後端的登入網址，
  再用預設瀏覽器或 `OpenBrowser` 開啟。
- 回呼網址帶著實際監聽的 port 與 `state` 參數，例如 `http://127.0.0.1:53682/callback?state=...`。client 只等帶著這個 state
  的導回，因為瀏覽器裡任何網頁都能對 loopback 位址送出請求。
- 它回傳 `RelaySignInResult`，內含代碼與 code verifier，由應用程式送給後端，以 `RedeemAppCodeAsync` 兌換。錯誤導回、沒有代碼
  的導回、逾時（`Timeout`，預設 5 分鐘）與取消，都是失敗結果。

provider 只看得到後端，所以有後端的桌面應用程式也能用 Sign in with Apple 與 GitHub 登入，而且不必隨程式附上 client secret。
見[桌面與主控台應用程式](../guides/desktop.md#經由後端登入)。

### ASP.NET Core 中轉的 loopback 回呼網址

`OAuth2AppRelayOptions.AppRedirectUris` 接受 loopback 網址：`http`、位址 `127.0.0.1` 或 `[::1]`，以及一段 path，不帶 query、
user information 或 fragment。

- 不帶 port 登記的網址，例如 `http://127.0.0.1/callback`，比對時接受同一位址與 path 的任意 port，如 RFC 8252 第 7.3 節所述。
  帶 port 登記時只接受那個 port。
- 請求的 loopback 網址可以在最後帶 43 到 128 個 base64url 字元的 `state` 參數，中轉會把它放在代碼之前一起導回。
- `localhost`、這兩個位址的其他寫法，以及不是 `Uri` 寫出形式的網址，都會被拒絕。
- 使用者電腦上任何程式都能監聽 loopback port，所以不帶 port 登記時，這樣的程式可以讓中轉把它自己發起的登入導回給它。
  應用程式若能固定監聽同一個 port，請帶 port 登記。
- `OAuth2Options.IsAppRedirectUri` 不變，所以 `AppOAuth2Client` 仍然拒絕 http。

### 有後端的應用程式

指南「前後端分離的應用程式」改為[有後端的應用程式](../guides/separate-back-end.md)：由後端登入，不分 provider，OpenID Connect
provider 也一樣。指南不再建議前端把 ID token 或 access token 送給後端。

## 破壞性變更

### 移除 access token 查證

- **影響對象：** 呼叫 `OAuth2Client.GetUserInfoAsync(accessToken)`，或設定 `OAuth2Options.AcceptedClientIds` 的後端。
- **原本：** 後端向 Google、LINE、Facebook 或 GitHub 查證前端取得的 access token 發給哪個 client 之後，回傳它所屬的使用者。
  其他 provider 擲出 `NotSupportedException`。
- **現在：** 兩個成員都已移除，使用它們的程式碼無法編譯。從組態繫結 options 時（例如用 `ConfigurationBinder`），名為 `AcceptedClientIds` 的 key 會被忽略。
- **遷移：** 改由後端登入。網頁前端走後端的網頁登入；Android、iOS 或 Mac Catalyst 上的 .NET MAUI 應用程式以 `WebAuthenticator`
  經由後端中轉登入，桌面應用程式與 Windows 上的 MAUI 則以 `LoopbackRelayClient` 經由後端中轉登入。之後由後端發出自己的
  session。見[有後端的應用程式](../guides/separate-back-end.md)。
