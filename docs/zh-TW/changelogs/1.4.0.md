# Polhem.OAuth2 1.4.0 — 發佈說明

[English](../../en/changelogs/1.4.0.md) | **繁體中文**

本檔是 [CHANGELOG.zh-TW.md](../../../CHANGELOG.zh-TW.md) 中 `[Unreleased]` 條目的詳細內容，這一版將成為 1.4.0。

本版新增 GitHub、Sign in with Apple 與其他任何 OpenID Connect provider，回傳前端送給後端的 access token 所屬的使用者，
並讓專屬的 OpenID Connect provider 檢查登入取得的 ID token。

## 新功能與變更

### GitHub

`GitHubOAuth2Options` 以 GitHub 登入，GitHub App 與 OAuth App 都可以。`UserId` 是數字帳號 ID。使用者不公開 email 時，改從
`/user/emails` 取得主要且已驗證的 email；這個請求失敗時 `Email` 為 null，登入不會因此失敗。GitHub 每次換 token 都要求
client secret，所以 public client 也會送出；行動應用程式要經由後端中轉登入 GitHub。見 [GitHub](../providers/github.md)。

### 前端送來的 access token 所屬的使用者

`OAuth2Client.GetUserInfoAsync(accessToken)` 回傳前端取得、交給後端的 access token 所屬的使用者。取得使用者資訊之前，
會先向 provider 確認 token 是發給 `ClientId` 或新增的 `OAuth2Options.AcceptedClientIds` 之一，而且這項查證無法跳過。
被拒絕、已過期或發給其他 client 的 token 是失敗結果。

| Provider | 支援情形 |
|----------|----------|
| Google、LINE | 支援。 |
| Facebook、GitHub | 支援。需要 `ClientSecret`，而且只接受發給 `ClientId` 的 token。 |
| Microsoft Entra ID、Auth0、Okta | 擲出 `NotSupportedException`，訊息指向 ID token。 |

見[前後端分離的應用程式](../guides/separate-back-end.md)與 [ADR-007](../../adr/adr-007-access-token-from-front-end.zh-TW.md)。

### 其他任何 OpenID Connect provider

`OidcOAuth2Options` 可以登入其他任何 OpenID Connect provider，例如 Keycloak 或 GitLab。端點可以手動設定，也可以由
`OidcOAuth2Options.FromDiscoveryAsync(authority)` 讀取，其文件的 issuer 必須是傳入的 authority。

- `ProviderName` 必填，因為使用者以它識別。
- `UserInfoEndpoint` 可以留空，這時使用者改從登入取得的 ID token 讀取。
- 它讀取的每個 ID token 都必須發給這個 client，設定了 `Issuer` 時也必須由它簽發；使用者資訊的 subject 必須與 ID token 相同。

見[其他 OpenID Connect provider](../providers/openid-connect.md)與
[ADR-008](../../adr/adr-008-generic-openid-connect-provider.zh-TW.md)。

### Sign in with Apple

`AppleOAuth2Options` 讓網頁應用程式以 Apple 登入。

- 套件以 `PrivateKey`（Sign in with Apple key 的 `.p8` 檔）、`KeyId` 與 `TeamId` 簽署 client secret（ES256 的 JSON Web Token），
  並在到期前重簽。也接受放在 `ClientSecret` 的預先簽好的 secret。
- `UserId` 與 `Email` 來自 ID token，姓名來自 Apple 只在使用者第一次登入時送出的 `user` 參數。
- `LoopbackOAuth2Client` 與 `AppOAuth2Client` 會拒絕這組 options，行動應用程式要經由後端中轉登入。

見 [Sign in with Apple](../providers/apple.md)與 [ADR-009](../../adr/adr-009-sign-in-with-apple.zh-TW.md)。

### form POST 回呼

要求 `name` 或 `email` scope 時，Apple 會從它自己的網站以 form POST 回到回呼網址。

- `OAuth2Client.UsesFormPostResponse` 回報 provider 是否以這種方式回來。
- Polhem.OAuth2.AspNetCore 與 Polhem.OAuth2.AspNet 的 `OAuth2Manager` 會從 POST 回呼的 form 讀參數，並把這類 client 的
  進行中登入放在 `SameSite=None` 的 cookie，瀏覽器才會在那個請求帶上它。其他 client 維持 `SameSite=Lax`。這類 client 的
  回呼必須接受 POST，並排除在 antiforgery 驗證之外。
- `AuthorizationCallback.User` 與接受它的建構式，讓兩個網頁套件以外的伺服器端框架能把 Apple 的 `user` 參數交給
  `CompleteAuthorizationAsync`。

見[網頁應用程式：登入狀態怎麼保存](../guides/web-sign-in-state.md)、[其他伺服器端框架](../guides/other-server-frameworks.md)與
[ADR-005](../../adr/adr-005-web-sign-in-cookie.zh-TW.md)。

### 安全性強化：檢查登入取得的 ID token

Google、Auth0、Okta 與 Microsoft Entra ID 會比照 `OidcOAuth2Options` 檢查登入取得的 ID token：它的 audience（`aud`）必須是
這個 client，使用者資訊的 subject（`sub`）也必須與它相同。Google 另外檢查 issuer（`iss`）是 `https://accounts.google.com`
或 `accounts.google.com`，Auth0 檢查 issuer 是授權或 token 端點的主機加上結尾斜線，例如 `https://<Domain>/`。Okta 與
Microsoft Entra ID 的 issuer 不由設定決定，不檢查。

原本會成功的登入，在下列情況改為以 `OAuth2Exception` 失敗：

- ID token 無法讀取；
- ID token 發給其他 client；
- Google 與 Auth0 的 ID token 指定了其他 issuer；
- 使用者資訊的 subject 與 ID token 不同。

token 回應沒有 ID token 時（例如沒有要求 `openid`）不檢查。

這些是 OpenID Connect Core 1.0 第 3.1.3.7 節與第 5.3.2 節要求 client 做的檢查，因此只會擋下違反規範或在傳遞途中被竄改的
回應，沒有需要遷移的步驟。2026-10-20 以真實帳號在加上這項檢查後登入這四家 provider，每次登入都成功；細節見
[ADR-008 的測試結果](../../adr/adr-008-generic-openid-connect-provider.zh-TW.md#測試結果)。

### LINE 只從發給自己 channel 的 ID token 讀取 email

LINE 的 ID token 的 authorized party（`azp`）不是 channel ID，或除了 channel ID 之外還有其他 audience 卻沒有 authorized
party 時，email 會留空。LINE 不會發出這兩種 token，預期登入結果不受影響。見 [LINE](../providers/line.md)。

### 送往 provider 的請求

- 每個送往 provider 的請求都在 `User-Agent` 標頭以 `Polhem.OAuth2/<版本>` 標明函式庫，排在應用程式傳入之 `HttpClient`
  預設 `User-Agent` 的內容之後。GitHub API 會拒絕沒有 `User-Agent` 的請求。
- token 請求一律送 `Accept: application/json`。RFC 6749 本來就規定 token 端點回傳 JSON；GitHub 沒有這個標頭時會以表單編碼回傳。
- token 端點以狀態碼 200 回傳、卻帶有 `error` 的回應，會成為帶著 provider 錯誤代碼的 `OAuth2Exception`，不再是「沒有
  access token」的泛用錯誤。GitHub 的 token 端點就是這樣回報失敗。
