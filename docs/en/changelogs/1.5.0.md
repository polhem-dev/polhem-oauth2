# Polhem.OAuth2 1.5.0 — Release Notes

**English** | [繁體中文](../../zh-TW/changelogs/1.5.0.md)

This file holds the details behind the 1.5.0 entry in [CHANGELOG.md](../../../CHANGELOG.md).

This version settles how an application with a back end signs in: the back end runs the sign-in, for web, mobile and now
desktop applications, and the front end no longer hands it a token. Applications without a back end sign in directly, as
before. [ADR-011](../../adr/adr-011-back-end-signs-in.md) records the decision.

## New features and changes

### Desktop applications sign in through the back end

`LoopbackRelayClient` signs a desktop or console application, or the Windows platform of a .NET MAUI application, in through
the back-end relay of its own ASP.NET Core back end:

- It creates the PKCE code verifier, listens on a loopback address, and asks the application for the back end's sign-in URL
  for the redirect URI and the S256 code challenge it receives. It opens that URL in the default browser, or with
  `OpenBrowser`.
- The redirect URI carries the bound port and a `state` query, such as `http://127.0.0.1:53682/callback?state=...`. The
  client waits only for the redirect that carries that state, because any web page open in the browser can send a request
  to a loopback address.
- It returns a `RelaySignInResult` with the code and the code verifier, which the application sends to its back end to
  redeem with `RedeemAppCodeAsync`. An error redirect, a redirect without a code, a timeout (`Timeout`, 5 minutes by default)
  and cancellation are failed results.

The provider sees only the back end, so Sign in with Apple and GitHub become available to desktop applications with a back
end, without shipping a client secret. See
[Desktop and console applications](../guides/desktop.md#signing-in-through-the-back-end).

### Loopback redirect URIs in the ASP.NET Core relay

`OAuth2AppRelayOptions.AppRedirectUris` accepts loopback URIs: `http`, the address `127.0.0.1` or `[::1]`, and a path, with
no query, user information or fragment.

- A URI registered without a port, such as `http://127.0.0.1/callback`, matches the same address and path on any port, as
  RFC 8252, section 7.3, describes. One registered with a port matches that port only.
- A requested loopback URI may end with a `state` query of 43 to 128 base64url characters, which the relay returns ahead of
  the code.
- `localhost`, other spellings of the two addresses, and URIs that are not written the way `Uri` writes them are refused.
- Any program on the user's computer can listen on a loopback port, so with a registration without a port, such a program
  can be relayed a sign-in it started itself. Register a port when the application can always listen on the same one.
- `OAuth2Options.IsAppRedirectUri` is unchanged, so `AppOAuth2Client` still refuses http.

### Applications with a back end

The guide [Apps with a separate back end](../guides/separate-back-end.md) is now
[Applications with a back end](../guides/separate-back-end.md): the back end signs in, with every provider, OpenID Connect
providers included. It no longer recommends that a front end send an ID token or an access token to its back end.

## Breaking changes

### The access token check is removed

- **Who is affected:** back ends that call `OAuth2Client.GetUserInfoAsync(accessToken)`, or set
  `OAuth2Options.AcceptedClientIds`.
- **Before:** a back end could return the user of an access token that its front end obtained, after asking Google, LINE,
  Facebook or GitHub which client the token was issued to. The other providers threw `NotSupportedException`.
- **Now:** both members are removed, and code that uses them no longer compiles. Binding the options from configuration, for
  example with `ConfigurationBinder`, ignores a key named `AcceptedClientIds`.
- **Migration:** have the back end sign in. A web front end signs in through the web sign-in of the back end. A .NET MAUI
  application on Android, iOS or Mac Catalyst signs in through the back-end relay with `WebAuthenticator`, and a desktop
  application, or MAUI on Windows, with `LoopbackRelayClient`. The back end then issues its own session. See
  [Applications with a back end](../guides/separate-back-end.md).
